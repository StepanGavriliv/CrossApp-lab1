# Лабораторна робота №2  
**Тема:** Публікація .NET застосунків у різних режимах

## Опис
У цій лабораторній роботі створено крос‑платформний застосунок **CrossApp**, який складається з двох проєктів:
- **Core** — бібліотека, що збирає інформацію про середовище (ОС, архітектура, RID, runtime).
- **Cli** — консольний застосунок, який викликає Core і виводить зібрані дані у консоль.

Мета роботи — дослідити різні варіанти публікації .NET застосунків, порівняти їх розмір, кількість файлів та особливості запуску.

# Order Domain – Інваріанти та демонстрація

## Інваріанти
1. **Id та Customer не порожні**  
   Перевіряється у методі `Order.Create`.

2. **SKU не порожній**  
   Перевіряється у `OrderLine.Create`.

3. **Quantity > 0**  
   Перевіряється у `OrderLine.Create`.

4. **Не можна підтвердити порожнє замовлення**  
   Перевіряється у `Order.Confirm`.

5. **Не можна змінювати підтверджене або скасоване замовлення**  
   Перевіряється у `Order.AddLine`.

6. **Стани замовлення (Draft, Confirmed, Cancelled)**  
   Перевірка допустимих переходів через `switch expression` у `Confirm` та `Cancel`.

##  Модуль звітів та аналітики (LINQ)

Цей розділ проєкту реалізує систему звітів та бізнес-аналітики для доменної області **«Замовлення»** (`Order`) на основі технології **LINQ**.

###  Доступні команди (CLI)
Програма підтримує запуск через аргументи командного рядка (`args`). Ви можете виконувати кожен звіт окремо за допомогою наступних команд:

*   **`dotnet run --project src/Cli -- report-top`** — виводить топ-3 найдорожчих замовлень у системі.
*   **`dotnet run --project src/Cli -- report-low`** — фільтрує та виводить замовлення, сума яких менша за порогове значення (< 1000 грн).
*   **`dotnet run --project src/Cli -- report-groups`** — групує замовлення за їхніми статусами (`Confirmed`, `New`), підраховуючи кількість замовлень у кожній групі та їхню загальну суму.
*   **`dotnet run --project src/Cli -- report-sum`** — виводить загальні підсумкові агрегати (загальна кількість, сума, середня сума та максимальне значення).

### 🛠 Технічні особливості реалізації
*   **Архітектура DTO (`StockLine`, `GroupSummary`):** Звіти використовують легкі незмінні записи (`record`), що повністю відокремлює шар відображення від внутрішньої доменної моделі (`Order`) та захищає її стани.
*   **Стабільне сортування (`ThenBy`):** Для сортування списків використовується комбінація `OrderByDescending`/`OrderBy` та `ThenBy(o => o.Id)`, що гарантує на 100% однаковий і детермінований порядок виводу навіть за наявності однакових сум замовлень.
*   **Відкладене виконання (Deferred Execution):** LINQ-запити формуються як плани виконання і матеріалізуються лише в момент виклику методів на кшталт `ToList()` чи ітерації.
*   **Безпечна агрегація:** Усі методи підрахунку (наприклад, `Totals`) містять перевірки на порожню колекцію даних, що запобігає виникненню винятків типу `InvalidOperationException`.

## Демонстрація
- **Сценарій 1**: створення замовлення, додавання рядків, підтвердження → успіх.  
- **Сценарій 2**: порушення інваріантів (порожнє замовлення, кількість = 0, порожній SKU) → винятки.  
- **Стан після відмов**: об’єкт лишається у `Draft`, рядків = 0.  
- **DTO**: `ToDto` та `FromDto` для передачі даних у сховище.
